# Plume 开发任务分解

> 文档版本：v0.2  
> 更新日期：2026-07-27  
> 依据文档：[产品需求文档](./产品需求文档.md) v0.4  
> 目标版本：Plume 1.0 MVP

## 1. 分解目的

本文档将 Plume 1.0 的产品需求转换为可进入工程排期的开发任务。任务按优先级、模块、依赖和阶段出口组织；具体人日与迭代数量在团队规模、技术验证结果和设计稿完成后估算。

## 2. 优先级定义

| 优先级 | 定义 | 发布规则 |
|---|---|---|
| P0 | 1.0 必须具备，缺失会破坏核心流程、安全底线或已确认产品决策 | 未完成不得发布 1.0 |
| P1 | 1.0 强烈建议，明显改善完整性和体验，但可在功能冻结时降级或延后 | 逐项评估，不阻塞基础 MVP |
| P2 | 后续版本候选，当前仅保留架构扩展点 | 不进入 1.0 排期 |

## 3. 当前技术基线

以下是进入技术验证时的工作假设，不替代正式架构决策：

- 桌面框架：Tauri。
- UI：React + TypeScript。
- 本地核心：Rust。
- 数据库：PostgreSQL 14+。
- 首发平台：macOS 13+、Windows 10/11。
- 首发语言：简体中文、英文。
- 数据链路：应用本地核心直接连接 PostgreSQL，不经过远程服务端。

技术验证阶段必须用实测结果确认或调整上述选型。

| P1-04 | 数据编辑 | 检测记录被其他会话修改或删除，提示并发冲突 | P0-G11 |
| P1-05 | SQL | 多语句、多结果集展示与错误语句定位 | P0-E, P0-F |
| P1-06 | SQL | 收藏 SQL、名称和标签管理 | P0-I01 |
| P1-07 | SQL | 手动事务模式与持续事务状态提示 | P0-E03, P0-G11 |

## 6. P2：后续版本候选

| ID | 功能方向 | 说明 |
|---|---|---|
| P2-01 | 可视化结构修改 | 新增、修改、删除字段、约束和索引，并生成变更 SQL |
| P2-02 | Schema Diff | 对比两个数据库或 Schema 并生成迁移建议 |
| P2-03 | ER 图 | 关系浏览优先，是否支持编辑另行评估 |
| P2-04 | 云 IAM 认证 | AWS RDS、Azure、GCP 分别验证，不承诺同时支持 |
| P2-05 | Linux 发布 | 验证凭据设施、WebView 和不同发行版安装包 |
| P2-06 | 自动更新 | 双平台签名更新、失败回滚和隐私说明 |
| P2-07 | 导入能力 | CSV 导入、字段映射、预览、错误行报告和事务控制 |
| P2-08 | 数据库运维 | 会话查看、锁分析等轻量诊断；不扩展为完整监控平台 |
| P2-09 | 插件机制 | 仅在核心能力稳定并出现真实扩展需求后评估 |

明确不在当前路线内：其他数据库类型、云端账号同步、团队协作、备份调度、完整权限治理和 AI 自动执行 SQL。

## 7. 建议开发阶段

### M0 技术可行性门槛

范围：P0-A。  
出口：难点原型和双平台构建全部通过，关键选型形成 ADR。

### M1 内部 Alpha

范围：P0-B、P0-C、P0-D、P0-E、P0-F 的基础链路。  
出口：可连接数据库、查找表、运行与取消 SQL、查看结果，不包含数据编辑。

### M2 功能完整 Alpha

范围：P0-G、P0-H、P0-I。  
出口：PRD 核心流程全部可用，数据编辑具备事务和离开保护。

### M3 Beta / 功能冻结

范围：P0 功能收尾，选定可进入 1.0 的 P1 项。  
出口：不再增加功能，集中处理兼容性、性能、安全和双语问题。

### M4 Release Candidate

范围：P0-J。  
出口：AC-01 至 AC-10 全部通过，macOS 与 Windows 安装包完成签名验证，无阻塞级缺陷。

## 8. 关键路径与并行关系

### 8.1 主关键路径

```text
架构与技术验证 P0-A
  → 通用 IPC / 状态基础 P0-B
  → 连接管理 P0-C
  → SQL 执行 P0-E
  → 结果展示 P0-F
  → 数据编辑 P0-G
  → 安全与恢复 P0-H / P0-I
  → 发布验收 P0-J
```

### 8.2 可并行工作流

- P0-B UI 壳可在数据库技术验证期间使用模拟数据推进。
- P0-D 元数据层与 P0-E 编辑器界面可在连接协议稳定后并行。
- P0-F 表格组件可用固定数据集提前开发，并在结果协议完成后接入。
- P0-H 环境视觉与确认界面可先开发，但 SQL 风险检测依赖语句解析方案。
- P0-I 本地存储可与查询工作台并行，最终接入执行事件。
- P0-J 自动化测试和双平台构建从 M0 开始持续建设，不集中到项目末期。

## 9. 首轮排期输入条件

进行人日或 Sprint 排期前，还需要确定：

1. 开发团队人数及前端、Rust、测试、设计能力分布。
2. 是否已有可复用的设计系统、数据表格或 SQL 编辑器方案。
3. PostgreSQL 最高测试版本及实际用户常用版本分布。
4. macOS 和 Windows 代码签名证书的获取计划。
5. 开源许可证选择。
6. P1 中哪些功能被明确要求随 1.0 发布。

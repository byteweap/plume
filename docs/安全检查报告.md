# Plume 1.0 安全检查报告

检查日期：2026-07-31
对应任务：P0-J05

## 结论

本次检查未发现凭据持久化、诊断日志、Tauri IPC 权限或导出落盘方面的阻塞级问题。未使用的 opener 插件及其窗口权限已移除，生产 WebView 已启用原型冻结；仓库新增可重复的安全边界检查、Dependabot 更新配置和拉取请求依赖审查。

在线漏洞库扫描没有在本地执行，因此本结论不等同于证明依赖不存在已知漏洞。GitHub 上的依赖审查和 Dependabot 是在线补充门禁；发布候选版还必须确认这些检查成功。

## 检查结果

| 范围 | 结论 | 证据 |
|---|---|---|
| 凭据 | 通过 | 数据库密码、SSH 密码及私钥口令仅写入系统凭据设施；配置响应与 SQLite 均不包含秘密值。Rust 测试覆盖凭据生命周期、序列化和数据库持久化边界。 |
| 日志与错误 | 通过 | 统一脱敏边界覆盖 URI userinfo、秘密类键值、Authorization 值、PEM 私钥和 IPC 错误字段；panic hook 不输出 payload。 |
| IPC 与 WebView | 通过 | `main` 窗口仅保留 `core:default`；未使用的 opener 前后端依赖、插件注册和权限已移除。生产 CSP 只允许应用资源与 Tauri IPC，禁用 `unsafe-eval`，并启用 `freezePrototype`。 |
| 文件导出 | 通过 | 导出先写入目标同目录临时文件，完成后同步并原子替换；失败、未提交或取消不会留下伪完整目标文件，临时文件会被清理。 |
| 依赖完整性 | 通过 | npm 锁文件中的安装包均带 integrity 值；Cargo registry 包均带 checksum；锁文件不再包含 opener 插件。 |
| 漏洞持续检查 | 已配置 | npm 与 Cargo 每周由 Dependabot 检查；拉取请求使用 GitHub Dependency Review 拒绝引入已知漏洞的依赖变更。 |

## 可重复验证

本地结构化门禁：

```bash
npm run check:security
```

聚焦行为测试：

```bash
cargo test --manifest-path src-tauri/Cargo.toml credentials
cargo test --manifest-path src-tauri/Cargo.toml diagnostics
cargo test --manifest-path src-tauri/Cargo.toml exports
```

完整仓库门禁通过 `npm run check:all` 执行，并已包含安全边界检查。

## 漏洞扫描限制

- 本地 `npm` 锁文件以离线方式刷新，命令报告 `found 0 vulnerabilities`；由于没有连接实时 advisory 数据库，该结果只作为辅助信息。
- 本次未运行需要上传依赖元数据的在线 `npm audit`，也未安装需要从网络获取并持久化可执行代码的 `cargo-audit`。
- 合并与发布候选版验收必须检查 GitHub Dependency Review 和 Dependabot 的在线结果。若任一报告高危或严重漏洞，P0-J10 不得通过。

# 性能回归基线

P0-J04 将启动、空闲内存、对象树、首屏表数据和大结果集检查收敛为一个可重复命令：

```bash
npm run benchmark:regression
```

该命令依次执行核心应用、SQL 编辑器、虚拟化结果网格和生产包体基准。任何预算被突破、虚拟化失效或结果不正确都会返回非零状态。CI 在 macOS 与 Windows 构建任务中分别执行，避免用单一平台数据掩盖平台差异。

## 回归预算

| 范围 | 固定工作负载 | 时间预算 | 内存或体积预算 | 正确性门禁 |
|---|---|---:|---:|---|
| 应用壳 | 无连接冷渲染并完成本地状态初始化 | <= 2,000 ms | 空闲 JS 堆增量 <= 64 MB | 欢迎工作区可见 |
| 对象树 | 100,000 个对象按 8 种类型分组 | <= 250 ms | 额外堆 <= 32 MB | 每组 12,500 项 |
| 首屏表数据 | 201 行探测结果裁剪为 200 行，重复 1,000 次 | <= 500 ms | 额外堆 <= 32 MB | 保留下一页标识且只展示 200 行 |
| 大结果协议 | 10,000 行 x 40 列、10 个批次投影为网格行 | <= 250 ms | 额外堆 <= 32 MB | 行数、末尾单元格和截断状态正确 |
| SQL 编辑器 | 10,000 行 / 508,893 字符挂载并更新选择 | 挂载 <= 1,000 ms；更新 <= 100 ms | 堆增量 <= 128 MB | 选择文本正确 |
| 虚拟化网格 | 10,000 行 x 40 列挂载并滚动到底部 | 挂载 <= 1,000 ms；滚动 <= 100 ms | 堆增量 <= 128 MB | DOM 行 <= 40、单元格 <= 600、末行可达、列可调整 |
| 生产启动包 | Vite 生产构建 | 构建失败即失败 | 启动 JS <= 1,000,000 B；gzip <= 320,000 B；`dist` <= 2,500,000 B | 必须恰有一个启动 JS 入口 |

时间阈值有意高于当前实测，以吸收共享 CI 主机抖动，同时仍能识别数量级退化。内存基准使用 `node --expose-gc`，在固定输入构造完成后收集进程 JS 堆；它衡量应用保留的前端数据与视图开销，不把测试夹具本身误算为增量。

## 2026-07-31 基线

环境：macOS 26.5.1（Darwin 25.5.0，arm64），Node.js 24.10.0，npm 11.6.1。

| 测量 | 结果 |
|---|---:|
| 应用壳可用 / 空闲堆增量 | 81.26 ms / 18.03 MB |
| 100,000 对象分组 / 额外堆 | 2.81 ms / 6.83 MB |
| 首屏归一化 1,000 次 / 额外堆 | 0.76 ms / 2.36 MB |
| 10,000 x 40 大结果投影 / 额外堆 | 0.45 ms / 0.79 MB |
| 编辑器挂载 / 更新 / 堆增量 | 92.38 ms / 7.36 ms / 20.87 MB |
| 网格挂载 / 滚动 / 堆增量 | 44.68 ms / 6.76 ms / 25.05 MB |
| 网格初始与末端 DOM 行 / 单元格 | 25 / 260；4 / 50 |
| 启动 JavaScript | 811,822 B；gzip 251,522 B |
| 完整 `dist` | 998,693 B |

## 测量边界

- 应用壳基准从 React 首次渲染开始，到本地配置、草稿、历史和工作区初始化完成并显示欢迎页为止；模块解析、WebView 进程创建和操作系统窗口动画不在该数字内。
- 生产启动包预算限制冷启动必须解析和传输的前端代码；SQL 编辑器和结果网格继续作为延迟加载块单独验证。
- 数据库网络耗时由 PostgreSQL 集成环境决定，不能用共享 CI 的绝对延迟作为稳定门禁。首屏查询仍固定使用 201 行探测、展示 200 行，并通过集成测试验证实际协议。
- 发布候选版仍需在目标 macOS 与 Windows 设备记录完整桌面进程冷启动和稳定 RSS。若该实测超过 PRD 的 2 秒启动目标或相对本基线显著增长，应阻止 P0-J10 发布，而不是放宽自动化预算。

# Plume 架构

[English](architecture.md) · [简体中文](architecture.zh-CN.md)

本文记录 Plume 当前的架构边界，描述的是已经实现的行为，而不是完整目标产品。计划内容与约束性决策请参阅[产品需求文档](产品需求文档.md)、[开发任务分解](开发任务分解.md)和[架构决策记录](adr/README.md)。

## 设计目标

Plume 优先保证：

- 较小的桌面资源占用与快速交互。
- 优先保证 PostgreSQL 行为准确，而不是追求广泛的数据库兼容性。
- 对凭据和数据修改操作建立明确的安全边界。
- 在增加查询、结果和编辑能力时，各模块仍可独立演进。
- 面对包含大量数据库和对象的服务器时，界面保持响应。

## 系统边界

```text
┌────────────────────────── 桌面应用 ──────────────────────────┐
│                                                            │
│  React UI → 功能 API → Tauri 适配层 → Rust 命令边界         │
│                                         ↓                  │
│                              PostgreSQL 服务与会话          │
│                                         ↓                  │
└────────────────────────────────── PostgreSQL 网络协议 ──────┘
                                          ↓
                                  PostgreSQL 服务器
```

Plume 没有远程应用服务端。桌面进程直接连接 PostgreSQL。

## 依赖方向

```text
React 组件
  → 功能 API
  → 类型化平台适配层
  → Tauri 命令
  → 数据库服务
  → PostgreSQL 驱动
```

依赖指向功能与领域契约。React 组件不直接导入 Tauri API；Tauri 命令处理 IPC 契约转换，但不承载 PostgreSQL 查询逻辑。

## 前端边界

```text
src/
├── app/          全局组合与桌面工作区
├── features/     包含类型、API、UI 和测试的领域功能
├── i18n/         类型化英文与简体中文语言目录
├── platform/     特权运行时适配层
├── shared/       与业务领域无关的小型 UI 原语
└── styles/       全局视觉基础
```

规则：

- 功能模块通过自身 API 调用特权能力。
- 只有 `platform/` 可以导入 `@tauri-apps/api`。
- 可翻译的界面文字来自类型化语言目录。
- 状态默认保留在局部，直到多个独立使用方共享同一生命周期。
- 只有连接会话、标签页和后台任务证明存在需求后，才引入全局状态库。

## Rust 边界

```text
src-tauri/src/
├── commands/      Tauri 命令与响应整形
├── credentials.rs 操作系统凭据适配器
├── database/
│   ├── connection.rs  PostgreSQL 与 TLS 连接建立
│   ├── ssh.rs         SSH 认证、主机校验与端口转发
│   ├── session.rs     服务器会话与各数据库客户端
│   ├── query.rs       查询执行协议与活动查询所有权
│   └── metadata.rs    PostgreSQL 系统目录只读查询
├── error.rs       可安全返回 UI 的稳定错误
├── profiles.rs    版本化连接配置仓库
└── lib.rs         应用组合与命令注册
```

命令边界将内部错误转换为 `authentication_failed`、`session_not_found`、`metadata_error` 等稳定代码。驱动错误只作为技术详情，不是主要 UI 契约。

## 连接与会话生命周期

1. React 校验连接表单；Rust 将非敏感配置保存到 SQLite，将数据库与 SSH 秘密保存到操作系统凭据设施。
2. `test_connection_profile` 测试尚未保存的表单修改；编辑表单未填写新密码时，从系统凭据读取原密码。
3. `connect_saved_database` 在 Rust 中解析秘密、按需建立 SSH 隧道、打开初始客户端并注册服务器会话。
4. React 只接收不透明会话 ID，并管理已断开、连接中、已连接、忙碌、重连中、正在断开和异常状态。应用启动只恢复配置，不恢复会话。
5. 展开其他数据库时，注册表提供对应客户端；已有客户端会复用，否则使用内存中的服务器会话配置新建。
6. `check_database_session` 检查可选隧道并执行真实 PostgreSQL 健康查询；显式断开会关闭隧道并移除该会话拥有的所有数据库客户端。
7. 安全重连会先建立并注册替代会话，再移除旧会话，且不会重放触发断线的操作。

每个已保存连接配置都会把目标分类为开发、测试、预发布或生产，并带有用户选择的连接强调色。
对象树使用紧凑的环境语义色点；配置成为当前工作区所有者后，环境徽标会持续出现在工作区标题
与状态栏中，包括离线和错误状态。徽标同时使用固定的环境语义色和配置强调色，因此安全上下文
不依赖连接名称或短暂的会话状态来推断。

连接配置可跨应用启动保留，PostgreSQL 会话则不会。查询由前端先生成不透明查询 ID，
Rust 活动查询注册表再将该 ID 绑定到会话和数据库；命令完成或失败后均移除注册。
注册项同时保存 PostgreSQL 取消令牌和解析后的传输设置；取消请求必须匹配会话与数据库
所有权，并发的重复取消请求会复用同一次发送过程。
每个查询 ID 与结构化表数据提交 ID 还必须在任何数据库调用前，由进程级重放守卫原子认领。
认领记录永不释放，包括连接中断或结果不确定的失败；因此 IPC 重试、会话替换与恢复都不能再次
提交旧操作。重复 ID 返回 `operation_replay_blocked`，只有新的用户明确操作才会生成新 ID。

## 查询执行边界

查询工作区只向 Rust 发送语句边界模块解析出的纯文本 SQL、查询 ID、会话 ID 和数据库。
Rust 使用 PostgreSQL Simple Query 协议执行，因此当前范围可以包含 PostgreSQL 函数体，
“执行全部”也能保持多语句的服务端边界。响应按语句返回从零开始的语句索引、完成状态、
列名和列元数据（PostgreSQL 类型 OID、类型名、Schema 和类型类别）、文本格式值、空值、
实际行数、保留行数或影响行数。行数据固定按每批 256 行返回，并带有从零开始的批次偏移；
每次执行携带用户选择的共享保留预算，可选 100 至 10,000 行，默认 10,000 行。超出预算的
行以及后续语句结果继续从协议流排空并标记截断，不改写 SQL。Describe 失败
（例如请求包含多条语句）时返回明确的 `unknown` 类型，不猜测类型。查询 ID 在响应中原样
返回，前端只允许它完成对应标签页当前仍处于活动状态的请求。

发送请求前，前端安全层会使用 CodeMirror 的 PostgreSQL 语法解析器分析本次实际执行范围。
它遍历语句和可写 CTE 的语法节点，结构化报告 `DROP`、`TRUNCATE`，以及自身顶层不含
`WHERE` 的 `DELETE` 和 `UPDATE`。每项风险包含类型、等级、类别、语句与操作偏移、长度有界
的语句摘要及可识别目标对象。检测只读取语法树中的关键字节点，因此注释、字符串、引号标识符、
dollar-quoted 函数体及 `ALTER TABLE ... DROP COLUMN` 不会因文本相似而被误判为可执行操作。
风险分类完成后，查询工作区会在创建查询 ID 或调用后端前拦截用户 SQL。确认对话框列出连接名、
Host 与端口、Database、实际 Schema、环境、风险类型、目标和长度有界的语句摘要。取消不会产生
任何执行副作用；确认后也只有在标签页、SQL 文本、连接配置、会话与数据库仍和展示内容一致时，
才发送被冻结的执行范围，否则丢弃过期请求。表数据模块内部生成的读取语句继续使用独立的结构化
执行路径。

每个连接配置持久保存 `all`、`critical-only` 或 `off` SQL 风险提示策略。开发、测试和预发布
连接可选择任意等级；生产连接只能选择全部风险或仅严重风险，不能完全关闭。React 表单与 Rust
配置写入边界都会校验该约束；执行层还会把异常的生产 `off` 数据安全降级为 `critical-only`。
已有数据库迁移后使用 `all`，旧调用方缺少该字段时也默认采用 `all`。

生产连接遇到 `DROP`、`TRUNCATE` 等严重风险时还会增加第二重确认：操作人员必须准确输入当前
Database 名称，执行按钮才会启用。该要求使用对话框中被冻结的执行上下文并区分大小写；无条件
`DELETE` 或 `UPDATE` 等非严重风险仍使用普通确认，不额外要求输入。

取消包发送成功只会让前端进入等待确认状态；仅当同一执行返回 PostgreSQL SQLSTATE
`57014` 时才最终标记为已取消。若查询在竞态中正常完成，最终状态仍为成功。

前端从发起执行到收到终态响应计算用户感知耗时。活动查询只刷新界面中的已用时间，
不持续改写执行状态；进入终态后固定最终耗时。多语句成功结果会汇总返回行数、影响行数，
并明确提示任一语句是否发生结果截断。

PostgreSQL 查询失败会通过命令边界返回面向用户的消息，以及 SQLSTATE、严重级别和可选的
详情、提示、原始查询位置等结构化诊断信息；服务端内部查询的位置不对外暴露。前端在本次
执行的选区、当前语句或完整文档范围内，将 PostgreSQL 从 1 开始的 Unicode 字符位置转换
为 CodeMirror 使用的 UTF-16 偏移。只有已执行 SQL 仍与当前文档一致时，编辑器才选中并
滚动到错误字符；通知条则独立展示并允许复制技术详情。

查询执行结果暂存在标签页生命周期内，不写入草稿。结果数据协议已由 P0-F01 定义；P0-F02
通过懒加载的 React Data Grid 适配器展示保留批次，采用固定行高、行列虚拟化，并支持列宽
调整、键盘导航、矩形选择、类型化值展示和制表符分隔复制。查询工具栏选择本次执行的结果
预算，结果面板会明确提示已达到预算。点击行号可选择整行；复制操作会将当前单元格区域或
整行选择序列化为制表符分隔文本，并可选择包含列名。

CSV 与 JSON 导出均可选择当前语句的全部已保留行或当前矩形选择。前端发送携带所选列和
原始值的类型化任务请求，CSV 请求还包含表头选项、分隔符和编码；Rust 持有原生保存对话框，
校验已保留数据边界，完成 CSV 字段转义，并写出 UTF-8、带 BOM 的 UTF-8 或 UTF-16LE。
JSON 以缩进对象数组流式写入，保留 null，并为重复列名确定性补充后缀以避免值被覆盖。
各格式的进度事件按 UUID 隔离，共享导出注册表允许独立命令请求取消且不阻塞 UI。两种格式
都会先写入目标目录内的唯一临时文件；完整输出经刷新和同步后，才原子替换所选路径。取消或
任意写入失败会删除临时文件，且不会改动已有目标文件。

从对象树打开普通表时，应用会按连接配置、数据库、Schema 与表创建或激活专用表数据标签。
首屏加载复用现有可取消查询协议和虚拟化结果网格，并使用经过 PostgreSQL 标识符转义、带
有界 `LIMIT`/`OFFSET` 的只读 `SELECT *`。默认每页 200 行；每页额外请求一行探测记录，并在
渲染前移除，以便无需执行完整计数或排空结果集就能判断是否可进入下一页。用户可前后翻页，
也可选择每页 50、100、200 或 500 行；修改每页数量会回到第一页。结果表头负责排序：普通
点击会替换当前顺序，按住 Ctrl/Cmd 点击则通过 React Data Grid 原生多列排序追加或修改次级
条件。排序条件保存在表数据标签中，持续显示优先级和方向，变化时回到第一页，并编译为
PostgreSQL `ORDER BY` 列序号，从而避免重复或特殊列名产生歧义。未排序时工具栏会警告记录在
分页请求之间可能移动。应用会针对每个表和会话读取一次 PostgreSQL 索引目录：只有存在有效、
就绪、立即生效、非部分且非表达式的主键或唯一索引，并且所有键列均为 `NOT NULL` 时，表格才
标记为可编辑；主键优先。选中的键名、类型和有序列会保留给后续变更跟踪。键不存在或元数据
不可用时一律保持只读，表头会说明原因，不允许使用含糊条件定位行。新会话会重新判定，旧会话
的迟到响应不会覆盖当前状态。

表数据标签还持有一个可序列化、仅存在于前端的待提交变更集。现有行修改会保存原始行定位键、
页码与行位置，以及每个已修改单元格的原值和待提交值。新增行的每一列初始为显式 `DEFAULT`
状态，与 `NULL` 和字符串值（包括空字符串）严格区分。删除项保留定位键和完整原始行快照；
暂存删除时会移除同一行先前的单元格修改。不可变模型会合并重复编辑，并在值恢复为原值时移除
对应变更。该模型不会调用数据库命令；翻页、排序、筛选和查询完成都不会清空变更集，且只有
可靠键可编辑状态生效时，工作区 reducer 才接受新的暂存变更。

可编辑结果列复用 React Data Grid 原生编辑生命周期，但待提交值由 Plume 编辑器管理。显式模式
选择器严格区分文本值、`NULL` 和 `DEFAULT`；文本模式不会在 JavaScript 中转换 PostgreSQL
原始表示，因此空字符串、数字文本、JSON、日期、数组及其他由服务端定型的值会保持原样，直到
事务命令执行 PostgreSQL 类型转换。编辑器提交只更新本地变更集。待提交单元格会显示新值和
醒目标记，并通过悬停提示同时提供原值与待提交值。只读表以及结果中缺少任一定位键列的情况
不会启用编辑器。

只有可编辑网格已加载字段后，“新增记录”操作才会启用。操作会创建限定在当前页的本地 UUID，
并在虚拟网格末尾追加一行，所有单元格初始均为 `DEFAULT`；用户可通过同一编辑器将任意字段
改为显式 `NULL` 或文本，不会用空字符串替代未填写值。新增行永不进入查询协议，其行号单元格
提供撤销图标以移除本地新增项。切换页面时，页面限定的新增项会隐藏而不会在每页重复出现，
同时仍保留在标签的变更集中。

现有行的行号列提供删除图标。触发后只会暂存完整原始行快照和可靠定位键，移除该行先前的
单元格修改，禁止继续编辑并显示待删除样式；同一控件可恢复该行。提交前始终显示独立且不带
卡片边框的可折叠统一预览带，汇总新增、修改和删除行；其中保留 `DEFAULT`、`NULL` 与文本的
区别，展示单元格原值到待提交值，并列出每一行按顺序排列的删除定位键（包括复合键）。每个
预览项都携带原始页码和单元格位置；触发定位时会在需要时切换页面，等待该页加载完成，再通过
网格句柄滚动并选中目标单元格。这些交互不会执行任何写语句。

提交预览时，前端只把写入所需字段转换为结构化请求；本地行 ID、页码位置和原始展示快照不会
跨越命令边界。Rust 会验证可靠键形状、字段集合和显式值模式，再从当前会话的数据库配置打开
独立客户端，避免共享查询连接上的并发读取意外进入写事务。Schema、表、字段和类型名称都按
PostgreSQL 标识符引用；文本值通过参数绑定并从 `text` 显式转换为目录报告的类型，`NULL` 与
`DEFAULT` 保持 SQL 状态而不是哨兵字符串。删除、修改和新增在同一事务中执行，每项操作必须
恰好影响一行。任何验证、类型转换、约束或行定位失败都会显式回滚事务，并完整保留前端变更集
供修正和重试；成功时只提交一次，清空变更集并重新加载当前页。
相邻的“放弃全部变更”操作会原子地用空变更集替换暂存模型。由于网格的待提交值、新增虚拟行和
删除样式都完全派生自该模型，当前页会立即恢复为编辑前的查询快照，不发起查询或数据库命令；
先前的提交错误也会同时清除。

待提交表数据还会进入统一离开保护：关闭表标签时保护该标签；断开或删除连接配置时保护该配置
下所有存在变更的表标签；原生窗口关闭请求则保护整个工作区的所有变更表标签。模态框列出每个
受影响表及其新增、修改、删除数量，并提供“提交并继续”“放弃并继续”与“取消”。提交会逐表
复用同一事务命令，并在第一个错误处停止，失败项和尚未处理的变更集继续保留；放弃只清空本次
受保护的变更集，再继续原先的关闭、断开、删除或退出操作。在无法提供自定义桌面操作的浏览器
卸载场景中，应用也会启用平台标准的未保存工作提示。

表数据筛选栏可用 AND 组合多个条件，支持等于、不等于、字面子串包含、大于/小于（含等于
变体）、为空和非空。已应用条件保存在标签中，并将分页重置到第一页。筛选值永不进入 SQL
字符串：前端只生成声明为 text 的占位符并携带 PostgreSQL 原始列元数据，Rust 使用扩展查询
协议逐项绑定值。比较参数会从 text 转换为服务端报告的字段类型；选择值以 text 投影用于通用
传输，渲染前恢复原始结果元数据。本地核心会校验参数数量、text 转换和结果列形状。

## SQL 补全边界

CodeMirror 将本地 PostgreSQL 关键字和常见函数候选，与异步数据库目录候选合并。Rust 只
返回当前用户具有 `USAGE` 权限的非系统 Schema，以及其中的表、外部表、View、物化 View
和可见字段。前端按会话和数据库缓存正在进行或已完成的目录请求；失败请求会从缓存移除，
后续补全可以重试。

目录加载不会阻塞编辑器事务；数据库请求尚未完成时，本地候选仍可显示。CodeMirror 会
使用返回的 Schema 树解析限定名称和表别名。应用异步响应前，适配器会确认编辑器仍指向
同一会话和数据库，避免重连或切换标签页后显示过期候选。

## 元数据按需导航

元数据按层级加载：

1. 展开服务器时加载数据库、登录/组角色和表空间。
2. 展开数据库时按需建立客户端并加载对象分类数量。
3. 展开数据库对象分类时加载具体对象。
4. 展开 Schema 时加载常用 Schema 对象。

每个节点独立管理 `idle`、`loading`、`success`、`error` 状态。组件存在期间会缓存已加载数据。这样既不会在连接时读取整个服务器目录，也能形成明确的错误重试边界。

## SSL 语义

| Plume 模式 | PostgreSQL 协商 | 证书校验 | 主机名校验 |
|---|---|---|---|
| `disable` | 只使用明文 | 否 | 否 |
| `prefer` | 优先 TLS，允许回退明文 | 否 | 否 |
| `require` | 必须使用 TLS | 否 | 否 |
| `verify-ca` | 必须使用 TLS | 是 | 否 |
| `verify-full` | 必须使用 TLS | 是 | 是 |

`verify-ca` 和 `verify-full` 要求提供 PEM 根证书路径。任意 TLS 模式还可使用
PEM 客户端证书链及其匹配的、未加密 PKCS#8 PEM 私钥，两个客户端路径必须同时提供。
React、Rust 配置仓库与连接服务会分别独立执行这些校验。

命令边界会使用不同的稳定错误码区分证书文件缺失或不可读、证书内容无效、主机名不匹配
和其他 TLS 握手失败。证书内容与私钥内容不会被序列化到配置存储或写入日志。

## SSH Tunnel 语义

- 支持密码认证，以及加密或未加密的私钥认证。
- 可选单级跳板机；跳板端点与目标端点分别执行 SSH 握手、主机密钥校验和认证。
- 每个端点都必须匹配配置的 `known_hosts`；未配置路径时使用平台默认的
  `~/.ssh/known_hosts`。未知主机密钥与已变化密钥会使用不同稳定错误拒绝。
- 隧道监听随机回环端口。PostgreSQL TCP 连接使用该地址，但 TLS 服务器名仍保留原数据库
  Host，因此经过 SSH 时 `verify-full` 仍会校验数据库证书主机名。
- 一个服务器会话拥有一条隧道，其他数据库客户端复用该隧道的本地端点。健康检查会 ping
  两级 SSH；测试、断开与析构路径会关闭或终止隧道监听任务。

SSH 密码与私钥口令使用独立系统凭据引用。配置响应与 SQLite 只包含端点参数和文件路径，
不包含这些秘密或私钥内容。

## 本地数据模型

共享 SQLite 使用 `PRAGMA user_version` 执行迁移。v5 保留连接配置与查询草稿表，并新增
`query_history`、`workspace_snapshots`、`workspace_tabs`、带关联表的 `local_tags` 以及
键值形式的 `local_settings`。历史记录只保存执行元数据和 SQL；快照只保存标签元数据与未保存
SQL。结果集、密码、私钥和活动 PostgreSQL 会话永不写入该数据库。迁移在事务中完成，启用外键，
遇到高于当前版本的数据库会拒绝读取，不会猜测其结构。
每次用户 SQL 到达终态后追加一条历史记录，保存连接配置 ID、Database/Schema、实际执行 SQL、
耗时毫秒数、`succeeded`/`failed`/`cancelled` 结果状态和时间戳；结构化表数据读取不写入历史。
历史写入采用尽力而为策略，失败不会改变数据库操作向用户展示的终态。
历史写入与保留清理在同一个 SQLite 事务中完成。默认策略会删除早于 90 天的记录，并独立删除
最新 10,000 条之外的记录，任一条件满足即会删除。Rust 服务接收经过校验的显式保留策略，
后续设置界面可调整任一上限，而无需改变持久化语义。
当前工作区快照会在本地工作区变化后以事务方式整体替换。快照的显式结构只包含侧栏布局、
有序标签上下文和查询 SQL（包括未保存编辑），明确排除执行状态、结果行、暂存表数据编辑、
会话 ID、事务和凭据。只有连接配置与草稿初始化成功后才开始保存，避免启动时的空状态覆盖
可恢复快照。
启动时会在连接配置目录可用后读取快照和草稿。已删除连接对应的标签会被丢弃；快照 SQL 优先于
较旧草稿，不在快照中的草稿会追加恢复。所有表数据标签均以空行、空编辑、未判定可编辑性和空
执行状态恢复。可以恢复活动标签与布局，但不会自动重建连接、执行 SQL 或写操作、恢复事务，
也不会复用防重放操作 ID。

本地数据清理命令提供四个显式范围，并在执行前由界面分别确认：`history` 只删除查询历史；
`drafts` 删除查询草稿、工作区标签和快照；`cache` 删除 `cache.` 前缀的本地设置，并同步
失效进程内的对象树与 SQL 补全目录缓存；`all` 删除上述数据、标签、设置和全部连接配置。
全量清理会先断开活动数据库会话，再删除系统凭据存储中的数据库、SSH 和跳板机秘密；不会删除
用户选择的证书、私钥或 `known_hosts` 文件。非全量范围不会修改连接配置或系统凭据。

## 安全与隐私不变量

- UI 不直接建立 PostgreSQL Socket。
- 日志中不得出现密码、私钥内容或带凭据的连接 URL。
- Rust 诊断信息在写入 stderr 前统一经过脱敏边界，IPC 命令错误的消息、详情和提示在序列化前也经过同一边界。脱敏覆盖 URI userinfo、秘密类键值、Authorization 凭据和 PEM 私钥块；panic 只报告源码位置，不输出 panic payload。
- 前端只接收不透明会话 ID，不接收长期凭据。
- 涉及用户输入标识符的元数据查询必须参数化。
- 纯浏览器开发环境必须明确拒绝特权操作，不能伪造数据库操作成功。
- 保存的数据库/SSH 密码与 SSH 私钥口令使用 macOS Keychain 或 Windows Credential Manager，不进入 SQLite 或序列化配置响应。

## 测试策略

- **类型与静态检查：** TypeScript 严格模式、ESLint、rustfmt，以及拒绝警告的 Clippy。
- **现有自动化测试：** 前端校验、转换、分组与对象树交互测试，以及 Rust 错误、连接、元数据和会话单元测试。
- **单元测试基线：** `npm run test:unit-baseline` 固定覆盖 PostgreSQL URL 解析、标识符引用、SQL 执行边界、风险识别、类型化结果展示和表数据暂存变更；该基线已纳入 `npm run check`。
- **PostgreSQL 集成测试：** 使用一次性的 `plume` 与 `plume_secondary` 数据库验证真实连接、跨数据库会话和系统目录查询；第二套启用 TLS 的服务验证明文回退、加密协商、CA 与主机名校验及客户端证书认证；两套 OpenSSH 服务验证密码、加密私钥、单级跳板机、严格主机密钥、隧道健康与生命周期，以及 SSH + `verify-full`。Schema 测试数据会自行清理。
- **端到端核心流程测试：** `npm run test:acceptance` 从真实 React 应用交互覆盖到 IPC API 边界，按 AC-01 至 AC-10 编号固定连接、对象树、表数据、SQL、安全确认、导出、恢复和离线编辑流程；场景与后端集成测试的对应关系见 [验收测试矩阵](./验收测试.md)。该套件已纳入 `npm run check`。
- **性能回归：** `npm run benchmark:regression` 统一检查应用壳启动与空闲堆、10 万对象分组、表数据首屏、大结果协议投影、编辑器、虚拟化网格和生产启动包体；预算、当前实测和测量边界见 [性能回归基线](./性能回归基线.md)。CI 在 macOS 与 Windows 上分别执行。
- **安全回归：** `npm run check:security` 检查主窗口能力白名单、生产 CSP、原型冻结、未使用 opener 能力的移除、锁文件完整性元数据，以及 npm/Cargo 的 Dependabot 覆盖；聚焦的 Rust 测试覆盖凭据隔离、诊断脱敏、导出失败与取消时的原子落盘行为。检查范围、证据和漏洞库限制记录在[安全检查报告](./安全检查报告.md)中。

标准本地门禁：

```bash
npm run check
npm run build
cd src-tauri
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
```

仓库级 `npm run check:all` 会运行包含 `npm run check:security` 的完整本地门禁。隔离数据库测试依次使用 `npm run postgres:up`、`npm run test:postgres` 和 `npm run postgres:down`；CI 还会在拉取请求中审查依赖变更、执行性能回归、构建未签名的 macOS/Windows 安装包，并在 PostgreSQL 14、16 和 18 上运行测试矩阵。

手动触发的 [macOS 发布流程](./macos-release.md)会构建 macOS 13+ universal 应用与 DMG，通过注入的 Developer ID 证书完成签名和 Apple 公证并附加票据；签名、架构、Gatekeeper 或公证验证不通过的产物不会上传。签名凭据只保存在加密仓库 Secret 中，不进入应用配置。

## 当前限制

- PostgreSQL 会话只保存在内存中，重连始终由用户明确触发。
- 尚未实现可持续消费的结果分批流与事务所有权。
- 尚未实现数据编辑和对象操作。
- Linux 打包不在首个版本目标内。

这些限制属于产品待办事项，不能成为绕过上述架构边界的理由。
